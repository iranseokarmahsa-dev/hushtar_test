# hushyar_co

## اجرای محلی

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload
```

برنامه در `http://127.0.0.1:8000` در دسترس است. در حالت development ورود مدیر غیرفعال است.
برای دریافت خروجی‌های Graphviz در محیط محلی، ابزار Graphviz را نیز نصب کنید (در Debian/Ubuntu: `sudo apt-get install graphviz fonts-noto-core`).

## گردش تحلیل

1. پروژه را بسازید و مصاحبه را به‌شکل DOCX یا Markdown ورودی بارگذاری کنید. Markdown باید بخش `## داده‌های پروژه` داشته باشد و YAML اصلی را زیر همان عنوان قرار دهد؛ مفاهیم فقط زیر پاراگراف پشتیبان تعریف می‌شوند.
2. پرامپت اول را دانلود یا کپی کنید، اجرا کنید و فایل Markdown خروجی آن را جداگانه وارد کنید. Python خروجی را مستقل ذخیره می‌کند.
3. پرامپت دوم را جداگانه اجرا کنید. این پرامپت فقط متن مصاحبه و شناسه/عنوان اولیه مفاهیم را می‌گیرد و هیچ خروجی پرامپت اول یا کد اولیه‌ای در ورودی آن نیست.
4. خروجی Markdown مرحله دوم را وارد کنید. در این تحلیل، تکرار مفهوم در فهرست مقوله مادر و زیرمقوله مجاز است، اما تخصیص به دو مقوله یا زیرمقوله مستقل گزارش می‌شود. ویژگی‌ها و ابعاد باید به مفهوم و شاهد متصل باشند؛ ابعاد با شناسه به ویژگی مربوط پیوند می‌خورند. پدیده محوری فقط در بخش اصلی خروجی AI می‌آید و Python آن را در مدل پارادایمی تزریق می‌کند. پس از دریافت هر دو خروجی، Python آن‌ها را ادغام، شناسه‌ها و نقل‌قول‌ها را اعتبارسنجی، پوشش مفاهیم و شش مؤلفه را ممیزی، و کدهای پیشنهادی ناسازگار با جایگاه مدل را گزارش می‌کند.
5. اگر شاهدی با متن پاراگراف تطابق دقیق نداشته باشد، تحلیل متوقف نمی‌شود: تطابق فازی فقط امتیاز و هشدار ثبت می‌کند و نقل‌قول ورودی را تغییر نمی‌دهد. رکورد مربوط برای بازبینی پژوهشگر علامت‌گذاری می‌شود؛ وضعیت نهایی تحلیل در چنین مواردی incomplete خواهد بود. رکوردهای ناقص/نامعتبر به‌صورت جداگانه ثبت می‌شوند و رکوردهای سالم حفظ می‌شوند. خطای YAML نیز همراه شماره خط و ستون گزارش می‌شود. هشدارها و خطاهای رکوردی در Markdown و برگه‌های مستقل Excel («هشدار شواهد» و «خطاهای رکوردی») در دسترس‌اند.
6. در «بازبینی مفاهیم» و «تحلیل مستقل مصاحبه» نتیجه و موارد ممیزی را بررسی و در صورت نیاز ویرایش کنید.
7. «نمودار پارادایمی» را باز کنید. نمودار از مدل معتبر ذخیره‌شده توسط Python ساخته می‌شود و برای رسم آن درخواست هوش مصنوعی اجرا نمی‌شود.
8. نمودار را بزرگ‌نمایی کنید، جزئیات مؤلفه‌ها و شواهد را بازبینی کنید، فایل PNG یا SVG بگیرید یا با گزینهٔ چاپ مرورگر به PDF ذخیره کنید. Markdown نهایی، Excel، JSON و Word نیز در نتایج در دسترس هستند.

فایل Word باید DOCX باشد. جدول سه‌ستونی با سرستون‌های «متن مصاحبه»، «مفاهیم معنادار» و «کد» به‌صورت خودکار پردازش می‌شود؛ ردیف‌هایی که متن مصاحبه‌شان خالی است به شاهد قبلی تعلق می‌گیرند. شناسه‌های پاراگراف و مفهوم به‌طور خودکار ساخته می‌شوند. فایل Markdown ورودی باید شناسه پروژه، مصاحبه، عنوان، موضوع و آرایه `paragraphs` داشته باشد؛ هر مفهوم با `concept_id`، `title` و `initial_code` در آرایه `concepts` همان پاراگراف قرار می‌گیرد. فهرست مستقل مفاهیم استفاده نمی‌شود. در هر دو روش، پس از بارگذاری می‌توانید متن، مفاهیم و کدها را بازبینی کنید.

عنوان و موضوع پژوهش را در مشخصات پروژه ثبت کنید تا در پرامپت تحلیل استفاده شوند. خروجی‌ای که وضعیت `incomplete` دارد با همین هشدار در نتایج نمایش داده می‌شود. فونت وزیرمتن به‌صورت محلی برای رابط کاربری استفاده می‌شود. تولید فایل PNG/SVG از سمت سرور به ابزار اجرایی Graphviz (`dot`) نیاز دارد؛ پیکربندی Render آن را نصب می‌کند.

## تحلیل تلفیقی، گروه‌بندی مقوله‌ها، استخراج تم و مدل نهایی

1. از تاریخچه، مصاحبه‌های تأییدشده را برای یک اجرای تلفیقی انتخاب کنید.
2. پس از تأیید Pool فاز سوم، در «اجراهای تلفیقی» وارد گروه‌بندی مقوله‌ها شوید.
3. برنامه یک Prompt مستقل Markdown برای پنج مؤلفه غیرمحوری می‌سازد؛ پدیده‌های محوری مستقل در این مرحله گروه‌بندی نمی‌شوند.
4. Prompt را دستی در ابزار هوش مصنوعی اجرا کنید و خروجی Markdown را جای‌گذاری یا بارگذاری کنید.
5. Python خروجی را Parse و اعتبارسنجی می‌کند؛ فقط خروجی معتبر وارد بازبینی پژوهشگر می‌شود. گروه‌ها، موارد مستقل و تناقض‌ها باید تعیین تکلیف شوند.
6. پس از تأیید نهایی گروه‌بندی، در فاز پنجم وارد «استخراج تم» شوید. ورودی این مرحله فقط گروه‌های تأییدشده و مقوله‌های مستقلی است که پژوهشگر تأیید کرده؛ موارد مستثناشده و پدیده‌های محوری وارد نمی‌شوند.
7. Prompt و پاسخ فاز پنجم Markdown هستند. خروجی پنج مؤلفه را جداگانه تحلیل می‌کند و هر Category Unit را دقیقاً یک‌بار در یک تم یا فهرست بدون تم تعیین تکلیف می‌کند. تناقض‌ها، شناسه‌ها و ارجاع شواهد نیز اعتبارسنجی می‌شوند.
8. تم‌ها و واحدهای بدون تم را بازبینی کنید؛ ویرایش، ادغام، تقسیم، جابه‌جایی، تأیید یا رد تناقض‌ها نسخه‌دار و در تاریخچه ثبت می‌شوند. تأیید نهایی فقط پس از تعیین تکلیف کامل پوشش ممکن است.
9. در فاز ششم، پدیده‌های محوری مستقلِ تأییدشده را با نودهای فاز پنجم تلفیق کنید؛ پدیده اصلی، تفسیرهای جایگزین و تناقض‌ها با Markdown مبادله و اعتبارسنجی می‌شوند.
10. پس از تأیید پدیده محوری، روابط مستقیم، تفسیری یا فرضی میان نودهای تأییدشده را بررسی کنید. روابط پیشنهادی، اصلاح یا افزوده‌شده، ردها و نودهای بدون رابطه در تاریخچه ثبت می‌شوند.
11. در فاز هفتم، مدل نهایی نسخه‌دار فقط از نودهای فاز پنجم و پدیده و روابط تأییدشده فاز ششم ساخته می‌شود. ممیزی پوشش منابع، شواهد، شناسه‌ها و ارجاع‌ها را کنترل می‌کند؛ موارد نامعتبر یا تناقض‌های تعیین‌تکلیف‌نشده مانع ثبت مدل می‌شوند.
12. نمودار نهایی شش مؤلفه، تم‌ها و مقوله‌های مستقل را از همان مدل نسخه‌دار نمایش می‌دهد و SVG/PNG را از همان ساختار تولید می‌کند. پیوندهای ساختاری خاکستری فقط چیدمان را مشخص می‌کنند؛ رابطه‌های تجربی تأییدشده با فلش و برحسب نوع مستقیم، تفسیری یا فرضی با سبک متفاوت نمایش داده می‌شوند. جزئیات شواهد و منابع هر نود و رابطه در وب قابل مشاهده‌اند. پیوندهای `PARADIGM_EDGES` هیچ‌گاه به‌عنوان رابطه تجربی ثبت نمی‌شوند و نمودار و خروجی مصاحبه‌های منفرد مستقل می‌مانند.
13. نسخه‌های قدیمی نگه‌داری می‌شوند؛ با تغییر Snapshot یا تأییدهای بالادست، مدل قبلی stale و از نمایش/دریافت به‌عنوان مدل معتبر خارج می‌شود. این فاز تحلیل AI تازه‌ای اجرا نمی‌کند.

حجم Prompt هر مرحله به‌صورت کامل بررسی می‌شود و در صورت عبور از سقف، هیچ داده‌ای حذف یا کوتاه نمی‌شود. سقف گروه‌بندی، استخراج تم و سنتز نهایی به‌ترتیب از `SYNTHESIS_CATEGORY_GROUPING_MAX_PROMPT_CHARS`، `SYNTHESIS_THEME_SYNTHESIS_MAX_PROMPT_CHARS` و `SYNTHESIS_FINAL_SYNTHESIS_MAX_PROMPT_CHARS` خوانده می‌شوند؛ مقدار پیش‌فرض هرکدام ۴۰٬۰۰۰ نویسه است. تغییر نسخه تأییدشده مراحل بالادست، نتایج پایین‌دست را stale می‌کند.

## آزمون‌ها

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

## استقرار

در production مقدارهای `SECRET_KEY`، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را تنظیم کنید. پروژه‌ها در یک آرشیو مشترک ذخیره می‌شوند و به شناسهٔ کاربر جداگانه وابسته نیستند؛ دسترسی همچنان با حساب مدیر مشترک محافظت می‌شود و حساب‌های کاربری مستقل در برنامه تعریف نشده‌اند. پایگاه داده SQLite در `data/` ذخیره می‌شود؛ پیکربندی فعال Render در `render.yaml` دیسک پایدار را روی همین مسیر متصل می‌کند تا مصاحبه‌ها پس از redeploy باقی بمانند.
